### 前言
開發此遊戲主要是教育性旨為目的，讓 DDE330 軟體人員可以藉由此架構學習到軟體相關開發模式。  

1. 資料結構
2. 物件導向
3. 設計模式(MVC 架構)
4. 多人連線(SocketIO)
5. 前端/後端基礎應用架構

---
  
### 遊戲架構職責劃分

| 職責 | 類別 / 模塊 | 英文名稱 | 說明 |
|:--|:--|:--:|:--|
| 牌 | Tile  | Mahjong Tile | 負責定義麻將牌的種類:萬、筒、索、風牌、三元牌、花牌。  |
| 牌組 | Deck |	Mahjong Deck | 負責牌牆的生成、洗牌、發牌、摸牌（包括死牌區/嶺上牌）等管理。 |
| 玩家手牌 | Player / Hand | Mahjong Player | 負責追蹤單個玩家的狀態：手牌、外露的吃/碰/槓搭子、分數、花牌、過水狀態等。 |
| 規則 | Model / Rule16 | Mahjong Rule | 定義Taiwan 16張麻將規則，檢查手上牌符合哪些胡牌情況，包含:聽牌、胡牌，吃、碰、槓 |
| 計算台數 | Score | Tai Calculator | 專門負責判斷牌型（如清一色、天胡）以及計算最終的台數和結算金額。 |
| 流程控制 | Controller | Game Controller | 負責串聯所有邏輯：管理回合、處理動作優先級 (吃/碰/槓/胡)、呼叫 Deck 摸牌、呼叫 Score 結算。 | 
| 圖形介面 | View | templates/*.html & static/*.js/css | flask 負責視覺呈現。 接收 Controller 傳來的遊戲狀態數據，使用 HTML 結構、CSS 樣式和 JavaScript 動態渲染出您設計的麻將牌桌 UI。 |
  
### 詳細職責對應
| 核心元件 | 所屬層 | 具體職責 |
|:--|:--:|:--|
| Rule16 | Model | 以16張麻將規則，檢查手牌是否符合聽牌、胡牌。 |
| Score | Model | 以16張麻將胡牌結構解析、台數計算、流局結算。 |
| Deck | Controller | 牌牆生成、洗牌、摸牌 (含嶺上牌)。 |
| Player | Controller | 追蹤手牌、外露搭子、分數、過水狀態。 |
| MahjongGame | Controller | 回合管理、動作優先級判斷 (resolve_claims)、遊戲流程控制。 |
| WebApp.py 路由 | Controller | 處理 /get_state、/action/discard 等 API，橋接前後端。 |
| templates/desktop.html | View | 包含牌桌的靜態 HTML 結構和 Jinja2 模板變量。 |
| static/script.js | View	| 接收 JSON 數據，呼叫 Flask API，動態渲染牌張、處理點擊事件 (打牌、碰、吃)。 |
| static/style.css | View | 處理牌桌的佈局、牌張的樣式、四方對稱排版。 |

### 使用者介面 (UI) 設計概念
| 介面元素 | 設計方向 |
|:--|:--|
| 牌桌 | 採用模擬實體麻將桌的視覺，背景可選擇多種台灣特色場景（夜市、老宅、現代客廳）。 |
| 手牌區 | 牌面清晰放大，支援拖曳出牌或點擊確認出牌。手牌可一鍵排序（數字/花色）。 |
| 資訊面板 | 顯示玩家姓名/暱稱、門風（東南西北）、風圈、已連莊數、虛擬金幣。 |
| 動作按鈕 | 「吃、碰、槓、聽、胡、過」按鈕，在可執行時高亮顯示，並於限時內讓玩家選擇。 |
| 花牌/槓牌區 | 清楚展示已攤開的花牌和槓牌，不佔用手牌區空間。 |

1. 操作介面：
一鍵提示： 當玩家聽牌時，系統會提示目前可胡的牌張與張數。  
動作優先順序： 碰/槓 (優先) > 吃牌 (次之) > 摸牌。  
動畫與音效(option)： 搭配語音提示 (國語/台語) 增加臨場感。  

2. 遊戲模式-經典連線 (PVP)  
支援 4 人即時連線對戰。   
設有 底/台數設定 (新手場、普通場、高手場)，讓玩家依自身虛擬金幣選擇。   
戰績紀錄（勝場、胡牌率、自摸次數等）。  

3. 遊戲平台
平台：行動裝置或PC，以網頁行式進行  
類型：線上多人策略棋牌遊戲

### 遊戲流程
A. 遊戲準備階段  

    graph TD
        A[開始遊戲 (Start)] --> B(玩家登入/選擇模式);
        B --> C(遊戲模式);
        C -- 經典連線 --> D(選擇牌桌: 新手/普通/高手場);

        D --> G(等待配對/確認);
        E --> H(開始單機局);
        F --> I(開始挑戰局);

        G & H & I --> J(四人到位, 系統初始化);

        J --> K(發牌與開門);
        K --> L(莊家 17 張, 閒家 16 張);
        L --> M(檢查並自動補花);
        M --> N[遊戲正式開始];

B. 遊戲對戰循環

    graph TD
        N --> O(莊家打出第一張牌);
        O --> P{輪到下一家 (逆時針)};
        
        P --> Q(判斷是否有人可胡牌?);
        
        Q -- 是 (放槍) --> Z[胡牌結算 (見 C)];
        
        Q -- 否 --> R{判斷是否有人可碰/槓?};
        
        R -- 是 --> S(詢問玩家: 碰/明槓/不動作?);
        S -- 執行碰/槓 --> T(碰/槓者出牌);
        S -- 不動作 --> U{判斷是否有人可吃牌 (僅上家)?};
        
        R -- 否 --> U;
        
        U -- 是 --> V(詢問玩家: 吃牌/不動作?);
        V -- 執行吃牌 --> T;
        V -- 否 (或不可吃) --> W(玩家從牌牆摸牌);
        
        W --> X{摸到牌後是否可暗槓/加槓/胡牌 (自摸)?};
        
        X -- 是 (自摸) --> Z;
        X -- 是 (槓牌) --> Y(執行槓牌並補牌);
        X -- 否 --> T;
        
        T --> P;
        Y --> P;
        
        P --> P_END{牌牆剩餘張數是否足夠?};
        P_END -- 是 --> P;
        P_END -- 否 (剩 8 疊) --> Z_FLOW[流局結算 (見 C)];

C. 遊戲結算階段

    graph TD
        Z[胡牌結算] --> Z1(計算胡牌者台數);
        Z_FLOW[流局結算] --> Z1_FLOW(莊家連莊, 不計算金幣);
        
        Z1 --> Z2{胡牌方式?};
        Z2 -- 自摸 --> Z3(閒家與莊家依台數付費給胡牌者);
        Z2 -- 放槍 --> Z4(放槍者依台數付費給胡牌者);
        
        Z3 & Z4 --> Z5(金幣/積分增減與紀錄更新);
        
        Z5 --> Z6{是否莊家胡牌?};
        Z6 -- 是 --> Z7(莊家連莊, 風圈不變);
        Z6 -- 否 --> Z8(換下家做莊, 風圈是否換圈?);
        
        Z7 & Z8 & Z1_FLOW --> Z9[新一局開始];
        Z9 --> A;

### 遊戲流程總結

    A. 登入/配對 → B. 牌局準備 (發牌/補花) → C. 對戰循環 (摸/打/動作/胡牌判斷) → D. 牌局結算 (金幣增減) → E. 連莊/換莊 → F. 繼續遊戲或返回大廳
